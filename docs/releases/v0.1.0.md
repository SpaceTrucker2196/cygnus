# cygnus v0.1.0 — first tagged build

The S6 milestone build: the engine and shell are usable end-to-end
on real repositories.

## Engine (CygnusCore)

- Knowledge graph store (GRDB): append-only interval revisions,
  three knowledge layers, full observation provenance, FTS name
  search, revision diff, `cygnus verify`.
- Providers: LocalFS walk + content-addressed store + manifest-diff
  incremental re-index (no-op re-index mints nothing); FSEvents
  watch; git source refs.
- Extractors: SwiftSyntax (declarations/imports/nesting), tree-sitter
  Python and C.
- **Derived layer online**: `ImportRollupDeriver` — per-directory
  `core:dependsOn` module aggregates with counts, provenance-linked
  to the underlying import observations.
- Resource discipline: bounded extraction window, 3.5 GB soft brake,
  4.5 GB hard abort (walk + extract) — an index run aborts cleanly
  rather than exhausting the machine.

## App (river.io shell)

- Workspace sidebar with security-scoped bookmarks, relink flow, and
  a live memory meter against the 5 GB governor.
- Code Graph: containment outline + inspector with a source code
  pane (anchor line highlighted); 2D Flat canvas with spatial
  grouping (Area / Layer with a tests band / MVVM-MVC Pattern
  roles), tinted hull regions, stable anchor layout; tests draw
  blue throughout — nodes, connection lines, and cloud.
- Dark-factory ops dashboard: capability detection, production
  orders, CI runs, converge metrics, token-spend ledger, commits,
  fastlane screenshot strip, Pages site preview.
- Install Factory: copies the DF_Template skeleton
  (github.com/SpaceTrucker2196/DF_Template) into a repo without a
  ledger system — additive, never overwrites.

## Known limits

- 3D rendering removed (2026-07-24) pending a perf-budgeted return
  behind the `GraphRendererView` seam.
- UI test runner blocked by a login-session automation issue
  (environment, not product).
- Derived layer covers import rollups only; fuzzy renames and
  IndexStoreDB reference resolution are E6-remaining.
